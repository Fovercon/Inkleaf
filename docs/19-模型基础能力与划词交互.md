## 技术设计与顺序

1. 保持 main/services-host 为网络/密钥边界；兼容旧 services.json，新增 diagramProvider（缺省 plantuml）与有界 chat 请求。保留原三个动作，兼容旧调用。
2. renderer/modelClient 为应用/可信内置插件共用能力，统一任务生命周期；应用设置不属于插件。外部隔离插件尚无无提示模型/密钥权限，后续开放 SDK 需单独明确授权机制。
3. modelSelection 捕获不可变选文与视口位置；翻译浮窗、问询侧栏各自持有任务，停用/关闭/换文档取消。追问仅携带当前会话成功的完整轮次，有界历史。
4. 模型回复使用独立 MarkdownIt（HTML 关闭）+ KaTeX + DOMPurify，不走文档插件管线，不执行模型代码；图片必须逐次显式加载，不赋予本地文件能力。
5. 图表预设显式保存后生效，无自动故障切换到另一服务；连接测试使用未保存的表单参数，只发送固定演示图，不保存或重渲染当前文档。
6. 单元测试协议/边界，真实 Electron 测交互/渲染/开关；回归存储、插件、布局。商业模型效果需账号，不伪称已验证。
