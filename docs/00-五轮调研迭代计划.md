## 每轮执行协议（定时任务触发时遵循）

1. 读取本文件，找到第一个 ⬜ 的轮次并执行对应任务。
2. **每轮必须**：WebSearch 多角度调研（≥3 次）、结合仓库实际代码/文档现状、产出结构完整的中文文档（建议 ≥200 行），图表用 Mermaid（本仓库自己的渲染管线即可预览）。
3. 文档要求**有分析、有判断、有优先级**，不是功能罗列；引用的调研来源在文末列出。
4. 完成后：把上表对应行标记 ✅（附一句结果摘要），`git add -A && git commit -m "调研第N轮：<主题>"`。
5. 向用户输出本轮简报（产出、关键发现、下轮预告）。
6. **禁止**：修改 `src/` 下任何功能代码；创建/修改/删除定时任务；第 5 轮结束时不续期。

## 各轮详细要求

### 第 1 轮 — 功能差距深度调研
- 对比对象：Typora、Obsidian、Mark Text、Bear、Ulysses、Zettlr、Notable/Foam、VS Code（预览生态）、Notion（管理思路）。
- 维度：编辑体验、渲染能力、知识管理（双链/标签/属性）、视图模式、文件管理、搜索、导出、多端、性能、生态/插件。
- 产出：功能矩阵表（本软件 vs 各标杆）、差距分级（核心缺失 / 体验差距 / 已超越项）、每项差距的用户价值判断。
- 附：协作模型改版审视——UI/图标/更新/平台支持的变更清点与评价。

### 第 2 轮 — 优化方向与方案
- 基于第 1 轮差距清单制定路线：P0（不做会明显掉队）/ P1（体验升级）/ P2（差异化押注）。
- 每项含：目标、方案要点、技术路径、依赖关系、工作量估计（S/M/L）、风险。
- 输出三阶段路线图（近期打磨 / 中期体系 / 远期差异化），并列出"快速赢"清单。

### 第 3 轮 — 当前架构评审（现状说明书）
- 通读 `src/main`、`src/preload`、`src/renderer`、`src/shared` 全部源码。
- 产出：模块结构图、IPC 通道契约表、渲染管线数据流图、编辑-预览同步时序图、状态管理图（均 Mermaid）。
- 评审：模块边界与耦合点、代码规范符合度、可扩展性障碍清单（诚实指出问题，作为第 4 轮输入）。

### 第 4 轮 — 插件化架构设计
- 调研 VS Code 扩展机制与 Obsidian 插件 API 的设计（贡献点、激活事件、命令系统、沙箱）。
- 设计 Inkleaf 插件体系：插件清单（manifest）、生命周期、API 分层（核心/编辑器/渲染/视图/文件）、激活点（命令、markdown-it 钩子、CodeMirror 扩展、侧栏面板、文件格式处理器、主题）、安全与沙箱、版本与兼容策略、开发者体验（脚手架/热载/调试）、从当前单体到插件化的迁移路径。
- 产出含：目标架构图、插件生命周期状态机、API 分层图、一个示例插件的完整设计。

### 第 5 轮 — AI 时代竞争力战略
- 调研素材：用户既有研究库 `/Users/wangyuan/Desktop/MyCoach/ai-software-research/projects`（24 份主流 AI 产品分析）+ WebSearch（Notion AI、Obsidian Copilot、Khoj、NotebookLM、Mem、Reflect、AnythingLLM、PrivateGPT 等）。
- 分析：AI×笔记/文档赛道格局、各家切入点、本地优先（local-first）软件的差异化机会。
- 产出：适合 Inkleaf 的 AI 能力提案（语义检索/RAG、AI 编辑命令、自动标签与双链建议、文档摘要与问答、agent 工作流、BYO-key 模型无关接入）、与第 4 轮插件架构的协同（AI 能力作为一等插件）、竞争壁垒与不做什么（克制清单）。
- 收尾：更新本文件为完成态，写整体总结段。
