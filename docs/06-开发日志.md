## 2026-10-15 — v0.4.0 审查后的回归修复

上述“遗留全部关闭”的结论不足：原有 UI 检查中的部分 FAIL 只打印日志，没有让进程失败；ST3 也未要求编辑标记实际保留。审查复现了文档状态、索引和插件权限问题，本次补充修复与独立回归。

- 文档切换以实际编辑文件为准，关闭标签和重启恢复真正加载目标；读取目标期间的新输入再次保存，失败时保留 dirty 并阻止切换、关闭及文件操作。重命名、移动、删除同步所有标签，操作期间暂停输入，避免保存到旧路径。
- 缓存标签重新打开时核对磁盘内容和文件存在，保留撤销历史、主题和滚动位置；跨文档双链锚点在目标加载后解析。关闭文档取消待执行的预览。
- 索引只解析 YAML/JSON 数据，禁止 gray-matter 的 JavaScript 执行引擎；持久化缓存核对完整文件集合与 SHA-256。书库 generation、文件 revision 和真实路径边界防止旧扫描、删除事件及外部符号链接污染当前索引。文件集合扫描期间发生变化会重扫，缓存失效后重建使用新集合，避免漏掉启动期间新增的文件。
- 外部插件改在 opaque-origin iframe 中运行，以私有 MessageChannel 提交受权限检查的命令和渲染请求，无法访问宿主文件接口。激活失败、禁用、卸载和钩子异常清理全部贡献；命令与代码块处理器检查归属，懒激活失败不再递归。
- 插件 HTML 清理拒绝新增资源 URL、危险 CSS 和嵌套 template，保留原公式的安全内联样式与原链接；外部处理器按注册顺序先执行，再绑定任务框和双链事件。
- 统一 UI 断言，失败时经正常清理返回非零；增加故意失败的负向检查。会话写入串行原子落盘；package-lock 的根版本与 0.4.0 对齐。

本机验证：类型检查、43/43 独立回归测试、16/16 真实文档界面场景、5/5 真实 DOM 插件场景、完整源码 UI 回归和平台界面检查通过。更新安全检查在 macOS 为 42 项通过、1 项 Linux 原生测试跳过；3 项平台路径检查通过。Linux CI 增加相同回归入口，继续验证 x64/arm64 AppImage、实际安装 deb 和启动确认。正式发布与已安装应用的版本仍按独立发布流程处理。

外部插件当前提供命令、DOM 后处理和代码块处理器；直接使用宿主 DOM、文件接口、MarkdownIt 或同步 `when` 的旧插件需要迁移。设计文档已注明这些限制。
