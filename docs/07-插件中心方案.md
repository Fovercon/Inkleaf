# 07 · 插件中心（Plugin Center）方案

> 状态：基础界面已实现（v0.4.5）；生命周期与异常处理完善见下方 v0.4.6 记录。
> 背景：插件运行时（注册表 / 权限网关 / 沙箱 / 生命周期 / 懒激活）自 v0.4.0 起完备，自动化检查 plugin-check 全绿，但**没有任何用户可见的界面**——用户看不到已装插件、无法启停、不知道插件目录在哪、没有安装入口。本方案补齐界面层。

## 一、目标与非目标

**目标**
1. 一个「插件中心」对话框：列出内置与外部插件，展示状态 / 权限 / 贡献的命令
2. 启用 / 停用 / 重新加载 / 卸载，全部即时生效（走既有 `window.ink` 生命周期，不新造机制）
3. 安装入口：从文件夹安装（拷贝进插件目录）+ 打开插件文件夹（Finder）+ 刷新
4. 入口可达：菜单、命令面板、工具栏按钮

**非目标（本轮不做）**
- 插件市场 / 在线源
- 插件专属设置界面（manifest schema 里暂无 contributes.configuration）
- 热更新与签名校验（维持现有 manifest 校验 + 沙箱隔离）

## 二、架构

```
┌─────────────────────────────────────────────┐
│ 插件中心对话框（renderer/pluginCenter.ts）      │
│  列表渲染 / 操作按钮 / 订阅状态变化重渲染         │
├─────────────────────────────────────────────┤
│ pluginRuntime（既有）                         │
│  + pluginSnapshot()   导出 UI 快照（只读）      │
│  + onPluginStateChange(cb)  状态变化通知       │
│  生命周期仍走 window.ink.enable/disable        │
├─────────────────────────────────────────────┤
│ IPC 新通道（shared/ipc.ts CH 常量）            │
│  plugins:reveal     打开插件目录（Finder）      │
│  plugins:install    选文件夹→校验→拷入 plugins  │
│  plugins:uninstall  移入废纸篓                 │
├─────────────────────────────────────────────┤
│ plugins-host（既有）manifest 校验 / 穿越防护    │
└─────────────────────────────────────────────┘
```

要点：
- **UI 不直接碰 records**：pluginRuntime 暴露纯快照 `pluginSnapshot()`，对话框只读渲染；所有变更走生命周期 API，与测试钩子同一条路，避免第二套状态机
- **安装 = 主进程拷贝目录**：复用 plugins-host 的 manifest 校验（ID、版本格式、权限、命令命名空间和入口路径），目标目录 `userData/plugins/<id>`，已存在则报错。暂未实现 engines 兼容版本校验。
- **卸载 = 废纸篓**：使用 `shell.trashItem`；成功后清理运行实例与启停设置，失败保留原状态。按 manifest ID 查找目录，兼容旧安装的目录名与 ID 不同的情况。

## 三、界面设计

对话框复用 palette 浮层的暗化背景风格（`.pc-overlay`）：

```
┌─ 插件中心 ──────────────────────────── ✕ ─┐
│ ┌──────────────────────────────────────┐ │
│ │ ◆ 提示块（Callout）   [内置] [运行中]   │ │
│ │   bundled.callout@0.1.0 · 渲染        │ │
│ │   Obsidian 兼容的提示块语法            │ │
│ │   [停用]                              │ │
│ ├──────────────────────────────────────┤ │
│ │ ◆ Hello Inkleaf      [外部] [已停用]   │ │
│ │   hello-inkleaf@0.1.0 · 命令 渲染     │ │
│ │   ▸ 打个招呼（点击执行）                │ │
│ │   [启用] [重新加载] [卸载]              │ │
│ └──────────────────────────────────────┘ │
│ [打开插件文件夹] [从文件夹安装…] [刷新]       │
└───────────────────────────────────────────┘
```

- 状态徽章四态：运行中（绿）/ 已停用（灰）/ 加载中（琥珀）/ 出错（红，悬停见 message）
- 内置插件不可卸载/重载，只可启停
- 贡献命令行内可点击（走既有命令注册表）

**入口**：工具栏拼图按钮 `#btn-plugins` ｜ 菜单「文件 → 插件中心…」｜ 命令面板 `plugins`

## 四、IPC 契约（新增 3 通道）

| 通道 | 请求 | 响应 |
| --- | --- | --- |
| `plugins:reveal` | – | `void`，文件管理器失败时 reject |
| `plugins:install` | – | `{ ok, canceled?, error?, id? }`（选目录 → 校验 → 暂存复制 → 原子移入） |
| `plugins:uninstall` | `id: string` | `{ ok, error? }`，按 manifest ID 查找后移入废纸篓 |

安全边界：install 拒绝选中插件目录自身 / 无 manifest / manifest 非法；uninstall 仅允许 `<pluginsDir>` 直系子目录且 id 规范，路径拼接后 resolve 校验防穿越。

## 五、测试（TDD）

新增 `plugins-ui-check`（第 20 项）：
1. 工具栏按钮 → 对话框可见，列表 ≥2（bundled.callout + hello-inkleaf）
2. callout 显示「运行中」；点「停用」→ 徽章变「已停用」→ rerender 后预览无 callout
3. 点「启用」→ 恢复「运行中」→ rerender 后 callout 回归
4. hello-inkleaf 的贡献命令存在且可执行
5. 对话框可关闭

## 七、v0.4.6 完善记录

- 修复 registered/error 状态点启用无效；返回可等待的激活结果，通知加载状态并清除旧错误。仍保留并发去重、激活令牌和失败清理。
- 使用独立 localStorage 设置保存用户明确的启停选择；外部插件默认懒激活，明确启用的渲染插件在重启后恢复。临时重载不会改写选择；设置写入失败会提示并保留原状态。
- 刷新为新增插件注册命令，扫描失败不清空现有实例；重载保留停用状态，变更 manifest 时只启动一个替代实例。
- 安装使用 manifest ID，允许下载目录有中文或空格；拒绝重复 ID、递归复制、符号链接与特殊文件。主进程串行修改安装目录，失败清理暂存目录。
- 对话框提供操作锁、明确的取消/成功/错误反馈、重试按钮、不可用命令禁用、焦点恢复与 Tab 循环、窄窗口换行。启停后自动刷新当前文档预览。
- 验证：新增生命周期与文件系统回归，以及真实 Chromium 的 7 组插件中心场景和窄窗口检查；CI 的 macOS/Linux 检查加入 `test:plugin-center-ui`。完整应用插件检查不再依靠测试事件强制刷新预览。

本轮范围仍不包含在线市场、插件自动更新、专属设置与兼容版本协商。版本号更新为 0.4.6；正式 Release 和本机安装由后续发布流程处理。
