## 一句话概述

首次启动时从欢迎页选择"打开书库"后界面长时间无任何反馈（像是卡死）；强行退出后重新打开，从欢迎页选择单个 md 文件能打开，但左侧文件栏显示的却是上次选择的那个目录。

## 复现步骤

1. Linux 上全新安装 0.3.0 deb 版，首次启动应用（无历史会话）；
2. 在初次进入的主页面（欢迎页）点击「打开书库」，选择一个文件目录；
3. 等待——界面长时间没有任何反应（无加载提示、欢迎页不消失）；
4. 关闭软件，重新启动；
5. 再次从欢迎页点击「打开文件」，选择一个单个 .md 文件；
6. 该 md 正常打开，但观察左侧文件栏。

## 预期行为

- 步骤 2 选择目录后：界面应立即给出加载反馈（按钮 loading / spinner），目录扫描完成后欢迎页消失、左侧文件栏显示该目录的文件树；
- 若用户改为打开单个文件，文件栏应显示该文件所在目录（或明确提示"将在当前书库中打开"）。

## 实际行为

- 步骤 3：选完目录后界面完全无变化，无任何加载指示，无法区分"正在加载 / 已经失败 / 软件卡死"；
- 步骤 6：左侧文件栏显示的不是本次所选 md 的所在目录，而是步骤 2 中那个"看似没打开成功"的目录。

## 根因初步分析（基于代码走读，未在 Linux 实机复现）

三个因素叠加造成该表现，因果链如下：

### 因素 1：欢迎页的显示只与"是否打开过文件"挂钩，与"是否打开过书库"无关

- `src/renderer/src/main.ts:75`：`emptyState.classList.toggle('visible', !runtime.currentFile)` —— 只要没有当前文件，欢迎页就一直显示；
- `src/renderer/styles/app.css:576-585`：`#empty-state` 是 `position: fixed; inset: 60px 0 30px 0; z-index: 20; background: var(--bg)` 的**不透明全宽浮层**，盖住侧栏区域。

因此**即使书库成功打开、侧栏已填充文件树，用户仍然看不到任何变化**——侧栏被欢迎页的不透明浮层完全遮住。这是"选了目录没反应"观感的直接来源，与目录大小无关。

### 因素 2：打开书库会做两次全量目录扫描，且无任何加载反馈

- `src/main/ipc.ts:146-154`：`lib:open` 处理器对所选目录做一次递归全量扫描（`readTree`），完成后把 `libraryRoot` 写入会话（`patchSession`）；
- `src/renderer/src/main.ts:121-131`：渲染进程拿到 `lib:open` 返回的树数据后**并没有使用**（`treeData` 被丢弃），紧接着 `tree.refresh()`（`src/renderer/src/fileTree.ts:51-54` → `lib:tree`）又触发**第二次**全量扫描；
- `openFolderAction`（`src/renderer/src/main.ts:133-136`）全程没有 loading 状态、按钮不禁用。

目录较大或磁盘较慢时（如含大量子目录的家目录），两次串行扫描显著拉长"无反应"时间，叠加因素 1 的遮挡，用户完全无法感知进度。

### 因素 3：会话已持久化 + 打开单文件不切换书库

- 用户关闭软件时，`libraryRoot` 其实**已经成功写入会话**（因素 2 中 `lib:open` 扫描完成即持久化）——上次并非真正失败，只是界面没反馈；
- 重启时 `boot()`（`src/renderer/src/main.ts:740-748`）读到会话中的 `libraryRoot` 会自动恢复书库并填充侧栏，但因为 `lastFile` 为空，欢迎页再次显示（回到用户看到的"初次主页面"）；
- 用户选择单个 md 时，`openFileAction`（`src/renderer/src/main.ts:138-143`）只在 `runtime.libraryRoot` 为空时才会把该文件的父目录设为书库；此时书库已恢复为旧目录，于是**只打开文件、不切换书库**，文件打开后欢迎页消失，侧栏露出——显示的正是上次那个"没反应"的目录。

### 平台相关性

相关代码均为平台无关逻辑，**macOS 与 AppImage 理论上同样存在**；用户在 Linux deb 0.3.0 上实际遭遇。

## 修复建议（按优先级）

1. **欢迎页显示条件**改为 `!runtime.currentFile && !runtime.libraryRoot`（`src/renderer/src/main.ts:75`），或在书库打开后自动选中/展开文件树首个文件——直接消除"成功也无反应"的观感；
2. **复用 `lib:open` 返回的树数据**填充文件树，去掉 `tree.refresh()` 的第二次全量扫描；
3. **打开书库期间增加加载反馈**：欢迎页按钮进入 loading/禁用态，大目录扫描时侧栏显示骨架或进度提示；
4. **明确"打开文件"与已恢复书库的关系**：已有书库时打开库外单文件，可提示"是否切换书库到该文件所在目录"，避免目录"莫名复活"的困惑。

## 修复与验收（2026-10-15）

- 欢迎页只在没有书库、没有文档时显示；成功打开书库会展开侧栏、切换到「全部文件」，并直接显示返回的文件树。中央提示选择文档或新建，不再遮住目录栏。
- 移除渲染端的第二次全量读树。选择和加载期间显示状态、禁用打开按钮；失败恢复按钮并保留原书库和编辑内容。
- 打开库外单文件的菜单、欢迎页、拖拽、系统打开和最近文件入口统一切换到其父目录；库内文档保持原书库。切换前保存所有编辑，保存失败则阻止切换。
- 目录验证、扫描和会话落盘成功后才提交新书库。跨库或关闭时原子清除旧文档路径；同库启动保留标签恢复。关闭状态立即进入持久化队列，旧 watcher 的慢关闭不能覆盖新书库。
- 真实 Electron 验收直接点击首次选择书库后的文件行，并通过 `elementFromPoint` 确认目录可见、未被浮层覆盖；覆盖折叠/最近视图恢复、延迟加载、失败重试、单次读树、旧库无文档后打开库外文件、保存失败和空书库。主进程另有实际文件系统并发与失败回归。
